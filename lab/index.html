TASK 2.1

環境設定

目的安裝建立 AI 代理程式所需的基礎套件，作為整份筆記本的地基。
# Install the Strands Agents framework and tools
# %pip install strands-agents strands-agents-tools
strands-agents核心框架，提供 Agent、@tool 等類別／裝飾器。
strands-agents-tools官方現成工具集合，例如稍後用到的 calculator。
為什麼被註解？教學環境通常已預先安裝，因此程式碼被註解掉，避免重複安裝耗費時間；之後所有 from strands import ... 都仰賴這裡安裝好的套件。
TASK 2.2

建立你的第一個 AI 代理程式

目的用最少的程式碼建立能對話的代理程式，理解 Agent 物件的基本組成。
from strands import Agent

agent = Agent(
    callback_handler=None,
    model="amazon.nova-lite-v1:0",
    system_prompt="You are a helpful
        assistant that provides concise responses."
)

response = agent("Hello! Tell me a joke.")
print(response)
callback_handler=None關閉逐字串流輸出，讓結果一次性回傳，方便閱讀。
model="amazon.nova-lite-v1:0"指定底層 LLM 為 Bedrock 的 Nova Lite —— 輕量、低延遲，適合示範。
system_prompt定義代理程式的人設與行為準則：一個「提供簡潔回應」的助理。
呼叫 agent(...)把 Agent 當成可呼叫物件，驗證「模型 + 系統提示詞」已能正常對話。
TASK 2.3

為代理程式新增工具

目的讓代理程式從「只能聊天」進化成「能實際採取行動」，並理解代理程式如何自動判斷該用哪個工具，以及如何繞過判斷、直接呼叫工具。
from strands import Agent, tool
from strands_tools import calculator

@tool
def weather():
    """Get current weather information"""
    return "Sunny and O degree Celsius"

agent_with_tools = Agent(
    callback_handler=None,
    model="amazon.nova-lite-v1:0",
    tools=[calculator, weather],
    system_prompt="You are a helpful assistant..."
)

response = agent_with_tools("What is the weather in Seattle in Fahrenheit?")
🧮

calculator（內建工具）

直接從 strands_tools 匯入的現成工具，不需自己實作，開箱即用。

🌤️

weather（@tool 自訂）

用 @tool 裝飾器把普通函式註冊成工具；docstring 會被當作工具說明給模型參考。此處為示範，固定回傳「Sunny」。

🔗

多步驟工具鏈

「西雅圖溫度是幾華氏？」刻意需要先呼叫 weather 拿攝氏度，再用 calculator 換算——展示代理程式自主規劃步驟的能力。

自動工具選擇

math_query = "What is 25 * 4 + 18?"
response = agent_with_tools(math_query)

提出純數學問題，代理程式會自行判斷「只需要 calculator，不需要 weather」——展示模型的工具選擇邏輯，而非每次呼叫全部工具。

直接呼叫工具

result = agent_with_tools.tool
    .calculator(expression="2 + 3 * 4")

用 agent.tool.<工具名稱>() 語法，略過模型的自然語言判斷，直接呼叫底層工具函式。適用於除錯、單元測試，或已明確知道要用哪個工具時，節省一次模型推論。

TASK 2.4

設定記錄（Logging）

目的打開「黑盒子」，觀察代理程式背後的決策與呼叫過程，方便除錯與理解。
import logging
logging.getLogger("strands").setLevel(
    logging.INFO)

logging.basicConfig(
    format="%(asctime)s | %(levelname)s | %(name)s | %(message)s",
    level=logging.INFO,
    handlers=[logging.StreamHandler()]
)

logger = logging.getLogger("agent_activity")
logger.info("Creating new agent...")
logged_agent = Agent(callback_handler=None, model="amazon.nova-lite-v1:0")
setLevel(logging.INFO)把框架內部日誌層級調高，讓模型呼叫、工具觸發等訊息也會顯示。
basicConfig(...)設定輸出格式（時間戳記／層級／名稱／訊息）與輸出位置（主控台）。
自訂 logger在建立代理程式前後手動標記，對照你的程式碼執行點與框架日誌。
純觀測工具不影響代理程式行為，是正式環境排查問題的重要手段。
TASK 2.5

探索模型組態

目的學習如何客製化底層模型參數，而不只用預設設定，藉此控制回應風格。
from strands.models import BedrockModel

custom_model = BedrockModel(
    model_id="amazon.nova-lite-v1:0",
    temperature=0.3
)
custom_agent = Agent(
    callback_handler=None,
    model=custom_model)

Temperature 溫度參數

0.0（一致 / 保守）1.0（創意 / 多樣）
目前設定：temperature = 0.3

數值越低，回應越一致、越可預測；數值越高，回應越有創意、越多樣但較不穩定。此處選擇偏低的 0.3，代表希望代理程式回答較穩定一致。也展示了 Strands 的彈性：模型可以用字串快速指定，也可以用 BedrockModel 物件精細調參。

TASK 2.6

建立食譜助理代理程式（RecipeBot）

目的整合前面所學，打造具備真實應用價值的實例——一個能上網搜尋、回答烹飪問題的助理。
%pip install ddgs

@tool
def websearch(keywords: str, max_results: int = 3) -> str:
    """Search the web for information."""
    try:
        results = DDGS().text(keywords, max_results=max_results)
        return results or "No results found."
    except Exception as e:
        return f"Search error: {e}"

recipe_agent = Agent(
    callback_handler=None,
    model="amazon.nova-lite-v1:0",
    system_prompt="""You are RecipeBot, a helpful cooking assistant.
    Use the websearch tool to find recipes...""",
    tools=[websearch]
)
ddgsDuckDuckGo 搜尋套件，讓代理程式能「連上網路」查資料。
型別提示與 docstringkeywords/max_results 與 Args/Returns 說明，讓模型理解如何呼叫此工具。
try/except捕捉搜尋例外並轉成易讀錯誤訊息，避免代理程式因搜尋失敗而中斷。
角色化 system_prompt賦予「RecipeBot」身份，並明確指示使用 websearch，避免資訊過時或編造。

測試 RecipeBot：完整案例展示

response = recipe_agent("Suggest a simple recipe with chicken and broccoli.")

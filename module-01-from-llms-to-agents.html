Intro 什麼是 AI Agent?
AWS 將 AI Agent 定義為:能與環境互動、蒐集資料,並運用資料自主執行任務,以達成預先設定目標的軟體程式。它把技術從「你指揮的工具」轉變為「協助你以更少心力完成更多事的夥伴」。

!合成謬誤

Fallacy of composition:個別部分有效,不代表整合成完整系統後也會可靠運作。

核心挑戰 — 隨著輸入量、任務複雜度與輸出範圍增加,單靠 LLM 的可靠性會隨之下降,這正是催生 Agent 架構的起點。

自主性(Autonomy)是 Agent 行為的基礎，代表 Agent 能夠：

獨立追求目標 · 即時反應環境變化 · 感知並解讀周遭資訊 · 與其他 Agent 協作解決更大問題

L1
規則式自動化(RPA) 預定義動作與固定順序
例：從 PDF 擷取發票資料並存入資料庫
L2
動態流程 動作固定，但由路由器 / LLM 決定順序
例：依情緒分析結果分支撰寫客服郵件
L3
目標導向規劃 給定目標後自行規劃並執行，監督極少
例：跨系統自行解決問題的客服 Agent
L4
高度自主 跨領域運作，主動設定目標並調整策略
例：自主研究並整合資訊的策略型 Agent
⚠ 自主性提升，也帶來實作挑戰
Increased autonomy drives the need for frameworks

1推理迴圈問題

Agent 陷入持續思考卻不採取行動的狀態。

→ 回應變慢、方案不完整

2工具管理複雜度

需協調多組 API 與系統，整合成本高。

→ API 使用效率低、延遲增加

3錯誤復原能力

面對非預期結果（如系統中斷）時難以應變。

→ 流程失敗、客戶滿意度下降
